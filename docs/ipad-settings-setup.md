# iPad Settings — Unity wiring guide (Issue #13)

Everything for the settings app lives inside **`Tablet_manager.prefab`**, the same way
the Camera and Gallery apps do. No per-scene manager objects, no edits to the base
`Tablet.prefab`.

## How the prefab is structured (why this works)

`Tablet_manager.prefab` is a **prefab variant** of `Tablet.prefab`. It inherits:
- the `ScreenManager` and all five screens — including an **empty `SettingsScreen`**
  that is already assigned to `ScreenManager.settingsScreen`,
- the home-screen **Settings icon, already wired to `ShowSettings()`**.

The variant then adds the app content (ViewFinder, Shutter, Gallery…) and the managers
(`PhotoLibrary`, `EvidenceGradingManager`, `TabletPersist`) **on the prefab root**.
Settings follows the identical pattern:

| Piece | Where it goes |
|---|---|
| Settings UI controls | children of the inherited `SettingsScreen` |
| `iPadSettingsPanel` (UI logic) | component on `SettingsScreen` |
| `SettingsManager` (JSON persistence) | component on the `Tablet_manager` root |
| `SettingsApplier` (applies to world) | component on the `Tablet_manager` root |

`SettingsApplier` holds **no scene references** — it auto-finds the directional light
and the BNG locomotion components after every scene load, because the tablet persists
across scenes while those objects are recreated. `SettingsManager` destroys only its
own *component* when a duplicate exists (e.g. the main menu's copy persisted into the
experience), so the tablet itself is never destroyed by the singleton check.

Data flow: `control → SettingsManager (writes settings.json + event) → SettingsApplier → scene`.
The main menu (#12) writes the same file, so menu and iPad override each other.

## Editor steps

The UI is **generated by an editor script** — `SettingsScreenBuilder`
(`Scripts/Settings/Editor/`) — which builds all controls inside the prefab, wires every
`iPadSettingsPanel` reference, hooks CloseButton → `ShowHome()`, and adds the two
managers to the root. Safe to re-run any time (it rebuilds `SettingsControls` from
scratch).

1. **Compile check** — open the project, Console must show zero errors.
2. Make sure `Tablet_manager.prefab` is **not open in Prefab Mode**.
3. Run **Tools ▸ Crime Scene ▸ Build iPad Settings Screen**.
4. Open `Tablet_manager.prefab` and eyeball the generated `SettingsScreen ▸
   SettingsControls`. Tweak spacing/colors freely — re-running the tool resets them.
5. Both `CSHouse` and `CS_Outside` pick the prefab change up automatically.
   (`SettingsApplier` forces BNG's `LoadLocomotionFromPrefs` off at runtime — no
   per-scene rig changes needed.)
6. **Cleanup** — delete `Assets/IPadSettingsScene.unity`, the empty
   `Assets/_Game/Scenes/Flow/IPadSettingsScene.unity`, and the temporary
   `SettingsControls` prefab asset if one was created earlier.

## Test checklist

1. Play `CSHouse` directly → tablet ▸ Settings icon → controls show saved values.
2. Night button dims the scene; speed buttons change movement speed; teleport toggle
   swaps locomotion.
3. `settings.json` updates at `%USERPROFILE%\AppData\LocalLow\<Company>\<Product>\`.
4. Change a setting in the main menu, enter the experience → world reflects it; change
   it on the iPad → overridden in the same file.
5. Teleport `CSHouse ↔ CS_Outside` → settings persist and re-apply in the new scene.
6. Restart Play → settings load from disk.
